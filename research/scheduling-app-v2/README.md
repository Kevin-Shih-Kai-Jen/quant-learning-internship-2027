# 班伴 · 團隊排班工作室 v0.2

2026-09-25 新版。完整保留 `../scheduling-app/` 歷史原型，沒有覆寫它或搬動任何研究資料。

這是可以操作的**本機單一管理者試用版**。可從建立群組一路完成需求確認、排班、修改、發布版本與匯出。沒有收費 API、前端建置依賴或外部字型。不是已可上架收款的商用服務。

## 啟動

需 Node.js 22 以上。在本目錄執行：

```sh
npm start
```

開啟 <http://127.0.0.1:4173>。不需要 `npm install`。不要直接以 `file://` 開啟，ES modules、Worker 和離線服務需要 HTTP。若埠被占用，可用 `PORT=4174 npm start`。

伺服器只綁定本機 `127.0.0.1`，只提供白名單靜態檔案，不會暴露研究庫其他資料。此伺服器不是正式多人後端。

首次會建立「日和咖啡」示範工作空間與完整草稿。可以直接修改，也能建立自己的空白群組；兩者資料分開。手機窄畫面在頁面上方切換群組。

## 可實際使用的流程

1. 建立群組與成員，設定每人班數上限。
2. 建立 1–14 天期次、固定每日班別、人數、截止時間與本期規則。
3. 管理者在本機代填「未填／可以排／希望排／不可排」，逐人確認。未填或未確認都不能安排。
4. 檢查缺交與可排人數；明確凍結需求版本。
5. 產生最多三個有不同安排的完整可行方案。搜尋在 Worker 中執行、可以取消；Worker 限時 2.5 秒，前端另設 3.5 秒終止保護，80,000 節點上限。逾時不宣稱無解，也不宣稱最佳。
6. 先預覽差異，再套用方案；或者先建立空白草稿手動編輯。
7. 在班次／人員視圖檢查安排；右側列出每個人的可排與阻擋原因。移除後重新指派即可換人；新增安排會自動鎖定。手動鎖定在所有求解模式中保留。
8. 支援保留鎖定重排、只補空缺、全新候選。復原／重做最多 40 步並保存在本機。舊候選不能清除新增加的鎖定。
9. 發布前列出差異並再次驗證完整覆蓋與硬限制；不可原地改寫已發布版本。修改需求後必須重新凍結，並重新排班或明確驗證沿用草稿。
10. 匯出目前檢視版本的 CSV、完整 JSON 備份，或從設定頁列印／另存 PDF。JSON 還原先驗證並要求保留原資料。

桌面採週曆＋班次檢查器，手機採逐日卡片。支援 Tab、Enter、Escape 與班表格方向鍵；所有狀態有文字，不能只靠顏色。

## 自由文字

目前是**有限格式的本機解析器，不是 AI**。每行完整匹配才提供可確認規則，例如：

```text
週三 晚班 不可排
週五 早班 希望排
2026-10-01 全部 可以排
```

週幾按期次真實日期計算。無法理解或期次外的句子不會被偷偷部分套用；需要手動設定時段並確認。偏好與不可排分開。未連接第三方 AI，也沒有傳送備註到外部服務。

## 規則與資料邊界

- 共用同一個規則檢查器驗證求解、編輯、候選套用及發布：已確認可排、每期班數、每日班數、時間重疊（含跨午夜）、班距、最多連續工作日。
- 班數以班次開始日期歸屬當日。只有本期資料，尚未做跨期邊界、技能、法規工時檢查，不能宣稱符合勞基法。
- 目前只找完整覆蓋方案，不做最少缺班最佳化；找不到完整解時不會暗中忽略班次。空白草稿仍可手動探索安排，但有缺口不能發布。
- 本機截止時間只供記錄與流程提示；沒有伺服器排程、到期自動凍結或通知。
- 本機發布不會發送通知。沒有成員登入、邀請、隱私隔離、跨裝置同步或真正多人提交。
- `localStorage` 不是雲端備份。資料因瀏覽器／網址／埠而隔離；清除網站資料會移除。定期下載 JSON。另存的舊版 v1 資料未自動移入 v2。
- 可從備份還原；損坏資料會顯示復原頁並保留原文，絕不默默用示範資料覆蓋。容量錯誤不會讓記憶體假裝已儲存。
- 偵測另一分頁更新後，舊分頁不能直接覆蓋；需重新載入。這是本機樂觀版本保護，不是跨裝置協作鎖。
- 首次線上載入後，Service Worker 快取本機 App 檔案供離線重新開啟。不同平台的 PWA 安裝能力尚未全面測試。
- App 不宣稱測量 Mac 溫度或自動防過熱。有限時間運算與取消用來避免不必要的持續負载。

## 測試

```sh
npm test
```

不需外部依賴；包含獨立窮舉基準對照、限制邊界、版本不可變、備份驗證、儲存失敗與跨分頁覆蓋保護。

瀏覽器整合測試需先啟動 App 並提供 Playwright：

```sh
node tests/browser-smoke.mjs
```

可用環境變數 `PLAYWRIGHT_MODULE` 指向既有 Playwright 的 `index.mjs`、`BROWSER_EXECUTABLE` 指向既有 Chromium、`APP_URL` 指向測試網址。測試使用隔離的臨時瀏覽器設定檔，不碰日常瀏覽器資料；截圖產生於 `tests/artifacts/`（不提交）。

## 檔案與後續架構

| 檔案 | 責任 |
|---|---|
| `domain.mjs` | 資料模型、共用規則、發布、差異、自由文字規則、匯出、備份驗證 |
| `solver.mjs` | 可中斷有界搜尋，回傳可行／無解／資源限制三種狀態 |
| `solver-worker.mjs` | 背景執行與有限時間切片 |
| `storage.mjs` | 本機版本比對、失敗不改記憶體、毀損資料保留 |
| `app.mjs`、`styles.css` | 視覺流程、班表、成員需求、對話框與響應式呈現 |
| `server.mjs`、`sw.js` | 本機預覽與離線 App shell |

商用架構仍依 [原產品規劃](../docs/ai-scheduling-app-product-plan.md) 推進。這次保留輕量 Web 原型方便驗證操作；沒有把它聲稱為原規劃中 Flutter／CP-SAT／Supabase 的完成品。下一階段優先實作登入與租戶隔離、真正成員提交與截止後異動、雲端版本發布，再接具 schema 驗證與成本上限的 AI，以及具最佳化能力的 CP-SAT 求解。

年費仍以每群組 NT$990 為產品目標；此版沒有付款功能。歷史計畫的供應商模型、價格與商店規則需要在接入時重新查證。
