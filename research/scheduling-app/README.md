# 排班小站（MVP）啟動說明

這個版本是「可本機直接跑」的第一版 MVP，目標是先把核心流程變成立刻能驗證的狀態：

1. 建立群組
2. 建立員工名單
3. 建立排班期次與班別需求
4. 每位員工填寫可排性/偏好（可加自然語言備註）
5. 以回溯方式產生 1~5 組候選班表
6. 手動微調候選班表
7. 匯出 CSV 或 JSON
8. 求解前可行性預檢 + 可中止排班，降低高負載風險

## 快速啟動

這個 MVP 不依賴後端服務，直接打開 `index.html` 即可使用：

1. 用檔案總管打開 `scheduling-app` 資料夾
2. 用瀏覽器開啟 `index.html`
3. 第一次會看到預設示範資料，可以直接測試排班流程

或用簡單本地服務開啟（避免部份瀏覽器限制本機檔案權限）：

```bash
cd /Users/coolguy/.codex/.chatgpt-projects/g-p-6a8ad7dc606481919474d5424342a1c3/scheduling-app
python3 -m http.server 4173
```

然後瀏覽 `http://localhost:4173/`。

## 檔案結構

- `index.html`：頁面與面板
- `styles.css`：視覺樣式
- `script.js`：流程、排班引擎、資料儲存
- `README.md`：本檔

## 使用建議（跑整晚也穩）

- 初始建議 3~6 人、每班 1~2 人，先把流程跑通再加規模。
- 求解前先看「衝突提示」；若有提示，先調整不可排輸入會比直接排班省資源。
- 排班中若需要暫停，直接按「停止排班」，會立即中斷搜尋避免持續高 CPU。

## 版本限制（先行版）

- 目前僅為本地離線存放於瀏覽器 `localStorage`
- AI 自然語言解析尚為規則式雛形，不是通用 NLP
- 排班引擎是回溯 + 回溯分組，屬於可用但可優化的 MVP
- 目前尚未提供線上帳號、多人協作、通知、支付、外部日曆同步
- 本版本新增：求解前可行性預檢、耗時/節點摘要、中途可手動中止
- 本版本新增：長時間節能調節（背景/低電量/通宵時逐步降頻）

## 長夜運算（防燒機）建議

這版新增「運行模式」與「最長執行分鐘」設定，預設使用 `夜間節能（長時）`，預設上限為 240 分鐘。

- 夜間節能：每一段搜尋會留白小休眠，降低持續高負載，適合長時間整晚跑。
- 平衡：兼顧速度與耗電，適合正常白天試算。
- 加速：少休眠、速度較快，但會提高 CPU 與散熱。

- 長夜節能判斷重點（已內建）：
  - 視窗背景/隱藏時自動加大節奏放慢。
  - 切到背景或返回前景時會立即重估保護條件，避免繼續使用過舊的電量/節奏資訊。
  - 每 12 秒重新偵測一次電池狀態，低電量會提高節流等級。
  - 運行時間每增加一段會逐步提高節能等級，避免整夜持續高轉速。
  - 電池低於 5% 且未充電時會安全停止，以避免關機中斷求解。
  - 若無法讀取到電池資訊，系統會進入「保守模式」並在約 6 小時後自動保護停止。

建議：夜間做長算時，先把上限設為 `240`（四小時），留空將退回模式預設值，按 `0` 才會啟用「不限制」。

### 運行期間可觀測欄位

- 運行中 `候選...` 狀態列會即時顯示：
  - 當前節流倍率、電池狀態、背景/保護狀態
  - 若為保護中止，會在結果摘要保留停止原因

若你在夜間遇到候選數太少，可以：
- 放寬需求（檢查每班最小需求、是否有太多「不可排」限制）
- 降低每人上限衝突（例如 `每期上限/每日上限`）
- 先用 `平衡` 做快速預覽，再切回 `夜間節能` 做完整補齊

### Mac 使用建議（避免過熱）

- 儘量在接上電源的情況下進行最長 4+ 小時的整夜求解。  
- 不要同時執行大量其他高負載程式。  
- 若出現大量 CPU 佔用，先按「停止排班」保留現有候選；下次改用較低候選數或更短期間再求解。  
- 目前版本不支援直接讀取 Mac 溫度感測，僅能用節奏保護與電量保護降低負載；若要再強化，下一步可接原生輔助程式（如可選的桌面代理）讀取更精準熱點資訊。
